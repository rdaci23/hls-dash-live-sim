# hls-dash-live-sim

Private standalone HLS/DASH manifest simulator recovered from the
`feature/dummy-live-stream` branch of `original private tools project`.
See [source provenance](docs/extraction.md) for the original commit and adaptations.

## Getting started

Requires Node.js 20 or newer. Docker is needed for DASH and HLS MP4/VoD mode;
the bundled HLS sample and HLS proxy run directly in Node.js.

```sh
npm ci
npm run build
npm run hls
```

Open `http://localhost:8899/proxy.m3u8` in a compatible HLS player, or use the
LAN URL printed in the terminal on a device. Run the control UI in another terminal:

```sh
npm run fault-control
```

Visit `http://localhost:19090` to change segment failures, latency and other fault
settings. Both processes must run from the same directory or receive the same
`--fault-config /absolute/path/faults.json`. Stop the Node servers with Ctrl+C.

## Commands

Use `npm start --` before a CLI command:

```sh
# Bundled HLS sample without Docker
npm start -- livesim start --sim-type hls

# Inspect a remote HLS manifest while substituting bundled sample media
npm start -- livesim start --manifest-url https://example.com/master.m3u8

# Proxy the actual origin media instead
npm start -- livesim start --manifest-url https://example.com/master.m3u8 --no-dummy-content

# Start DASH with livesim2 in Docker and a local fault proxy
npm run dash

# Multi-period DASH manifest
npm start -- livesim start --sim-type dash --detach --periods 3 --period-durations 60,120,180

# Stop DASH (Ctrl+C also stops the companion Node proxy)
npm start -- livesim stop --sim-type dash

# List built-in and locally saved templates
npm run templates

# Run a built-in template with bundled HLS media
npm start -- sports-stream

# Save a template derived from a manifest
npm start -- create-manifest-template https://example.com/manifest.mpd --name my-stream
npm start -- dummy-stream my-stream --sim-type dash

# View all simulator options
npm start -- livesim --help
```

Optionally run `npm link` to use `hls-dash-live-sim` directly as a CLI.
`livesim stop` and `livesim logs` manage Docker containers; Node HLS servers are
foreground processes, including when `--detach` is supplied. For DASH, `--detach`
detaches the container while the Node fault proxy remains in the terminal.

## Configuration and scope

- `.hls-dash-faults.json`: created automatically; watched for live updates.
- `.hls-dash-manifest-templates.json`: personal templates generated by the CLI.
- `examples/faults.json`: a clean example configuration.
- `~/.hls-dash-live-sim/livesim2/repdata`: optional DASH cache.

Local configuration, saved templates, authentication files, build output and
dependencies are ignored by Git. Existing Standalone configuration and containers
use separate names. The recovered personal template file is not included because
generated templates can contain source URLs and credentials. The original saved
templates were recovered into the local ignored file at extraction time; they
remain available in this checkout but are not pushed to GitHub.

This is the recovered work in progress, with small standalone integration fixes.
Templates and manifest preservation describe test metadata; bundled HLS media
does not reproduce an arbitrary bitrate ladder, real DRM, ad insertion or true
low-latency encoding. DASH uses the original pinned livesim2 v1.7.0 image.
See the [fault guide](docs/fault-injection-guide.md) for the available controls.

## Validation

```sh
npm run typecheck
npm test
```

Tests exercise HLS playlists and binary segments, file-based fault changes,
cross-process control UI injections, HLS templates, DASH manifest parsing and
the DASH fault proxy without Docker. Full DASH backend playback requires a
running Docker daemon and is not covered by these tests.
