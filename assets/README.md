# Procedural media fixtures

The HLS and DASH samples are generated by `scripts/generate-fixtures.cjs` from
FFmpeg's `testsrc2` pattern and a synthesized 440 Hz tone. They use no external
footage, soundtrack, logo or client manifest. They replace the original recovered
prototype samples. A follow-up [historical-media investigation](../docs/historical-media-provenance.md)
traced the originals to their introducing commit and found strong reproducible
evidence of FFmpeg `testsrc` video plus synthesized 1,000 Hz tone. The exact old
command was not retained; current regeneration is explicit in the scripts.

- HLS: twelve seconds of 24 fps video; 180p and 360p H.264 Baseline renditions,
  muxed stereo AAC audio at 48 kHz, two-second segments and aligned keyframes.
- DASH: twelve seconds of 360p H.264 video with separate stereo AAC audio. Audio
  uses complete AAC access units; livesim2 handles the small padded tail while
  deriving live audio timing from the media. The MPD moves each representation's
  SegmentTemplate to AdaptationSet level for the validated livesim2 adapter.
- Optional DASH ABR: `scripts/generate-dash-abr.cjs` creates
  `assets/dash-abr-sample` with aligned 180p/360p H.264 Baseline video at
  180/600 kbps and separate 64 kbps stereo AAC. It uses the same procedural
  pattern/tone, 24 fps, twelve-second source and two-second random-access chunks.
  Both video representations share an AdaptationSet SegmentTemplate; coded
  dimensions and every source video fragment's timing/keyframe start are tested.
  The initial fixture was encoded with FFmpeg 7.1.1/libx264. Run
  `npm run fixtures:dash-abr` to regenerate only this optional ladder, leaving the
  existing HLS and single-rendition DASH baselines untouched. Rebuild afterward.
- The DASH generators use unformatted `$Number$` filenames, as required by that
  engine version. It does not rewrite source encodings to pretend to have different
  bitrates, resolutions or codecs.

- Optional HLS fMP4 ladder: `scripts/generate-hls-cmaf.cjs` creates
  `assets/hls-cmaf-sample` (about 3.5 MiB): 234p, 432p and 720p H.264 at roughly
  300, 900 and 2,270 kbit/s plus separate 96 kbit/s stereo AAC, from the same
  procedural pattern and tone with a white-corner / amplitude pulse. It is an
  exact eight-second loop of two-second segments; every segment holds four
  half-second fragments so the same bytes serve whole segments and low-latency
  parts. The generator folds FFmpeg's short trailing audio segment into the last
  full one, removes the AAC priming edit and records every part's byte range in
  `index.json`, which the simulator validates at startup. Run
  `npm run fixtures:hls-cmaf` to regenerate only this ladder. Initial generation
  used FFmpeg 7.1.1/libx264. [How it is served](../docs/generated-streams.md).

Run `npm run fixtures` with FFmpeg installed to regenerate. Encoded output and
bandwidth measurements may vary with FFmpeg/libx264 versions; the generated master
playlist records its actual measured ladder. Rebuild after regeneration. Stop live
sessions before replacing their media. Project-owned generated fixtures are covered
by the [MIT License](../LICENSE). External generation tools retain their own
licenses; see [third-party notices](../THIRD_PARTY_NOTICES.md).

Optional independent tracks: `npm run fixtures:tracks` creates `assets/track-sample`
from procedural FFmpeg testsrc2 and 440/880 Hz tones, plus authored EN/RO captions
using the owned fragmented-WebVTT builder. It includes genuine 180p/360p video and
an optional 540p third rendition, two separate AAC signals, HLS WebVTT and DASH
wvtt. The generator validates exact eight-second coded loops; no upstream media
or caption content is copied. Input audio is trimmed to account for AAC encoder
priming so the complete sample timeline aligns with video/text. The owned loop also includes a white-corner / audio-amplitude pulse for
independent A/V drift measurement; no third-party image/audio is used. AAC
initialization omits the priming edit while retaining its coded samples. Initial
generation used FFmpeg 7.1.1. [Setup, scope and verification](../docs/track-fixtures.md).
