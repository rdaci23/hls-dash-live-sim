# Current implementation and supported limits

This is the current behavior of the private 0.2.0 development line. Older reports
are listed in [verification history](verification-history.md); their test counts,
engine versions and limitations must not be read as the current state.
The project is standalone and has no external framework dependency. Supported baseline
streams must be valid; broken behavior belongs to explicit faults.

## Operation and isolation

- Servers bind to loopback unless LAN serving is explicitly enabled. Port
  collisions fail without killing the existing listener.
- LAN control requires a bearer token of at least 16 characters. The control API
  checks origins and loopback Host headers; static HTML/JS contain no credentials.
- Remote fetches require declared origins. Credentials stay scoped to the source
  origin and are removed on cross-origin redirects. Protocols, redirect counts,
  timeouts and transfer sizes are bounded.
- Docker sessions have management/workspace ownership labels. Management refuses
  unrelated containers. Shutdown and cancelled startup clean up the exact owned
  container, including a creation still waiting for Docker acknowledgement.
- Fault configuration is validated and saved atomically. Directory watching has
  a 250 ms polling fallback. Invalid edits retain the last valid configuration.
  Partial API saves merge fresh disk state under a cooperating-writer lock;
  concurrent writers receive HTTP 409. Manual file writers can still race.
- Independent sessions should use separate processes and fault files. Shared
  files deliberately share manual fault settings across processes.

## HLS

Generated samples use procedural 180p/360p H.264 Baseline and muxed AAC, with
aligned keyframes and two-second segments. LIVE has a sliding window, increasing
media sequence numbers, program timestamps and explicit loop discontinuities.
Both renditions share one time anchor. EVENT grows from startup; VOD ends.

Publication uses monotonic time plus a wall-clock anchor, so a system clock
correction cannot reverse the window. Removed segments remain available for a
grace period of their duration plus the longest window duration: 14 seconds after
removal with defaults. They then return 410; future segments return 404.

The origin proxy rewrites signed child playlists, alternate audio, initialization
maps and keys. A bounded registry keeps advertised resources reachable and retains
retired references for a grace period. Limits are 100,000 resources, 128 observed
playlists and 4 MiB per remote playlist. Capacity failure returns HTTP 503 instead
of silently evicting active references. Full-response buffering remains a limit.

Variable substitution (`EXT-X-DEFINE`), LL-HLS parts, blocking reload and delta
updates fail explicitly with HTTP 422. Scenario targeting currently supports
generated samples, not arbitrary HLS origins. The sample's muxed audio cannot be
targeted independently of video.

## DASH and clocks

DASH uses the procedural H.264/AAC fixture through livesim2 v1.15.3, pinned to an
immutable image digest in `dash-sim-runner.ts`. Its official image is AMD64-only;
ARM Docker hosts use emulation. Timing, segment availability and live periods are
generated by the engine. Media URLs stay relative and reachable through the proxy.
The adapter uses actual path options, waits for a valid live MPD and never invents
replacement segment aliases.

Source import parses bounded XML with namespaces, inheritance, codecs, separate
audio/video, reordered attributes and fractional durations. Media ticks are
converted through the timescale. An import analyzes metadata; it does not preserve
arbitrary source media, codecs or DRM.

Custom assets under `--vodroot` must contain a static, single-source-Period MPD
with AdaptationSet SegmentTemplates, plain `$Number$` without a timeline or
`$Time$` with a finite timeline, and local relative media paths. Representation
SegmentTemplates, BaseURL/Location, SegmentList/SegmentBase and formatted
identifiers fail preflight. This checks structure, not encoded-media correctness.
Uneven custom periods are rejected; use `--periods-per-hour` or supported equal
period durations that divide an hour.

Local `utc_head` is the default. MPD availability, media availability and UTC use
engine real time; the proxy forwards Date and exposes it through CORS. Clock
requests are excluded from media/manifest delay. `--utc external` deliberately
uses an internet-dependent clock. `nowMS` is a per-request diagnostic override;
it does not create coherent fixed-time/time-skew playback. A shared virtual clock
is not implemented.

The v1.15.3 engine fix withholds a new Period while an adaptation has an empty
timeline. Tests probe both Number and Time addressing around period boundaries;
no player exception is hidden or filtered to make baseline playback pass.

## Faults, scenarios and diagnostics

Manual faults cover media 403/404, completed malformed media, fixed delay and
manifest freeze. Network settings add a shared media bandwidth ceiling and
additional random media/manifest GET delay; see [network conditions](network-conditions.md). Corrupt range responses preserve Content-Range and byte length.
Client disconnect/shutdown cancels artificial delay and upstream work.

Freeze captures the latest observed HLS child playlist or DASH MPD and accepts
only off/always. DASH cache-busting queries do not bypass it. Manifest caches are
bounded to 128 entries; a new stream over capacity returns 503 until unfreezing.

One-shot faults consume one matching GET across resources. HEAD and abandoned
requests during artificial delay do not consume them. Durable arm IDs preserve
rapid reset/reinject changes; multiple unconsumed arms coalesce. Manual random
faults use unseeded 40% probability. HLS key faults require an encrypted remote
origin and are not commercial DRM or DASH faults. [Fault details](fault-injection-guide.md).

Immutable scenario files provide logical track/segment/attempt selection, session
time windows, seeded probability, ordered rules and application caps. The initial
404 preset asserts a nonempty successful retry of the same logical download and
byte range. HTTP success alone does not prove player recovery. Unknown identities,
capacity exhaustion and conflicting manual faults invalidate a run. More scenario
actions and ABR fallback assertions remain future work. [Rules](scenarios.md).

Session/request/fault IDs correlate response headers and redacted events for
selection, consumption, application and cancellation. No raw source URLs,
credentials, key/media bodies or labels are recorded. Memory retains 2,000 events;
optional JSONL capture stops at 10 MiB with explicit truncation. File errors are
reported. Incomplete/truncated evidence cannot pass a playback gate.
[Diagnostics](diagnostics.md).

## Control page and manifest inspection

The client preserves native `fetch` and enables actions only after connecting.
Latency accepts 0–60,000 ms. An omitted injection API value retains its 3,000 ms
default; explicit zero clears it and invalid explicit values return 400 without
changing configuration. Delay is persistent response latency, not a bandwidth cap.

The viewer reads the actual HLS playlist or DASH MPD directly from a local
simulator with its default proxy enabled. It requires ready health/session headers,
omits cookies and control authorization, rejects redirects and limits responses
to 4 MiB. HLS child choices come from same-origin variant/rendition declarations;
segments and keys are not fetched. Refresh is manual and respects manifest freeze.
The control server does not expose an arbitrary-URL fetching endpoint.

Connected details retain a root playback URL separately from the displayed HLS
child URL. Copy/download exports the successful displayed snapshot without a
network request and uses a fixed safe `.m3u8`/`.mpd` filename. URL/token edits,
session replacement and failed/in-flight manifest reads invalidate exports.
Raw exported relative URLs require the original simulator base.

Both protocols' `/health` responses expose a read-only manual-fault snapshot:
configured rules, one-shot armed/consumed state, response latency, jitter, shared
bandwidth ceiling and freeze.
Reading it does not call fault selection or consume/rearm anything. No config
path or credentials are returned. Scenario mode reports the scenario state instead.
The page distinguishes saved controls, unsaved edits and last-observed runtime
state; it never assumes a pasted URL shares the control process's fault file.

## Verification and release scope

Automated API/protocol tests, the control-page browser checks, real Docker
integration, HTTP scenario verification and a production-dependency package smoke
check are described in [development and CI](development.md). CI also compiles the
standalone SceneGraph tester; compilation is not a physical-device test.

Recorded full playback gates pass for Chrome hls.js/dash.js and Roku Express 4K
3940EU, OS 16.0.4 build 842: healthy playback, startup 404 and an injected 404 after
verified healthy rendering for each protocol. Normal browser UTC synchronization
remained enabled. [Exact acceptance gates and evidence](playback-gates.md).

Strict HLS retry cases use one rendition; healthy HLS checks use the two-rendition
ladder. Same-download retry evidence does not establish ABR fallback. The separate
[HLS ABR runner](hls-abr.md) verifies bandwidth-driven automatic downshift/upshift
on the two-rendition sample, with played-frame and server-download correlation. Browser
frame measurements do not establish perceived audio quality. Native audio/video
progress is sampled separately, excluding uninitialized UTC zeros.

No Roku requests to local UTC were observed. Its internal synchronization strategy
and internet-isolated playback remain unverified. Apple, Android, other Roku
models/OS versions, DASH/native or broader HLS ABR recovery, real DRM, ads, 4K and low-latency streaming
remain outside the verified support claim. Sports/news/OTT/mobile presets report
the sample's actual renditions/windows rather than promising those features.

The [release checklist](release-checklist.md) tracks licensing, notices and other
public-beta requirements. The repository and npm package remain private.
