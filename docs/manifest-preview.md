# Manifest inspection without consuming faults

**Connect stream**, HLS playlist selection and **Refresh manifest** display a fresh
baseline generated by the connected simulator. Local status, payload, latency,
freeze, publication and simulated edge-cache actions are bypassed for that request.
A preview does not seed or replace freeze snapshots, establish rollback history,
populate negative caches, or count as a retry. Publication and UTC keep running.
Metadata discovery can make an advertised preset available in the catalog. The
normal UI automatically previews a bounded set of advertised same-simulator HLS
child playlists to discover resource metadata; it never probes media/init/keys.
The last selected manifest text stays stable until explicit refresh/selection.

**Copy Playback URL** copies the ordinary URL, which still exercises the real
scenario. Use your player or an explicit HTTP probe for faulted responses. The
preview is clearly labeled; it is not evidence of what a player received during
a freeze or malformed-manifest scenario. **Copy original** and **Download original**
export the original preview text without another request, including when the view
uses readable XML formatting or line wrapping. Actual last-delivered fault bodies
remain outside this viewer's scope. The legacy shared-file page retains its older
**Load/Copy/Download Manifest** labels with the same preview handshake.

The viewer first checks `/health` for `manifestPreview: "baseline-v1"`. It sends
`X-Sim-Manifest-Preview: baseline-v1` and requires the same acknowledgment on the
response. Old peers are rejected before requesting a manifest; there is no raw
playback fallback. Only known root/advertised HLS playlists and the configured
DASH root MPD accept this header, and only with GET/HEAD. Bad versions, resource
kinds and methods return 400 before run controls or fault selection. Media, keys,
initialization and UTC cannot use it to bypass faults. Legacy `/pl?u=…` proxy
wrappers also reject previews; use the registered playlist URLs returned by the
manifest instead. Ordinary legacy requests retain their behavior.

The browser still accepts only local simulator URLs, sends no control token or
cookies to manifest origins, rejects redirects and bounds the preview body/time.
The simulator fetches only its configured origin and advertised resources under
the existing origin policy. Nested simulators receive the preview intent so an
edge inspection cannot consume an origin simulator's fault. A non-simulator
origin can still fail: the preview bypasses local simulator actions, not a real
upstream outage. A malformed source remains malformed.

## Verify

```sh
npm run manifest:preview -- --output output/manifest-preview
npm run test:ui
```

The isolated runner covers HLS and DASH manifest status/payload rules, advancing
previews during a freeze, rollback prerequisites, a layered negative cache and
rejection on media/init/UTC. It checks real playback failures afterward, cache
body identity, restoration, complete diagnostics and zero owned work after close.
Reports record the exact commit and dirty state; prototype evidence is not a
release qualification. Browser tests also verify that refreshing an armed
manifest fault leaves its selection count unchanged and that an unsupported peer
receives no manifest request. Neither result claims player recovery.
